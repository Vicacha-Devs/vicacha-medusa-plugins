# Admin

Medusa Admin extension — pages, shared components, and data-fetching hooks for the B2B plugin.

```sh
admin/
├── tsconfig.json         TypeScript config (moduleResolution: bundler, noEmit: true)
├── i18n/                 react-i18next setup and translation files
├── lib/
│   ├── client.ts         Medusa JS SDK client singleton
│   └── query-key-factory.ts  React Query key builder
├── hooks/
│   └── api/              React Query hooks — one file per domain
├── components/
│   └── common/           shared UI components (see below)
├── routes/
│   └── b2b/              page routes registered in the Medusa admin shell
│       ├── page.tsx            /b2b — overview dashboard
│       ├── companies/          /b2b/companies
│       │   ├── page.tsx
│       │   └── [companyId]/
│       │       └── page.tsx    /b2b/companies/:companyId
│       ├── quotes/             /b2b/quotes
│       │   ├── page.tsx
│       │   └── [quoteId]/
│       │       ├── page.tsx    /b2b/quotes/:quoteId
│       │       └── manage/
│       │           └── page.tsx  /b2b/quotes/:quoteId/manage
│       └── approvals/          /b2b/approvals
│           └── page.tsx
└── utils/                shared admin utilities
```

---

## Route registration

Each `page.tsx` exports a `config` object created with `defineRouteConfig` that provides the sidebar label and icon. Medusa's admin shell picks these up automatically when the plugin is loaded.

```ts
export const config = defineRouteConfig({
  label: "Companies",
  icon: BuildingIcon,
})
```

---

## Data fetching

All server communication goes through React Query hooks in `hooks/api/`. Hooks use the JS SDK client from `lib/client.ts`. Query keys are generated by `lib/query-key-factory.ts`.

Hooks follow the naming pattern:

- `use<Resource>s` — list query
- `use<Resource>` — single-item query
- `useCreate<Resource>` — create mutation
- `useUpdate<Resource>` — update mutation
- `useDelete<Resource>` — delete mutation

## Shared component library

Located in `components/common/`. All components are internal — they are not exported by the plugin's public API.

| Component | Purpose |
| --- | --- |
| `DataTable` | `@tanstack/react-table` wrapper: sorting, pagination, pluggable filters |
| `DataTableFilter` | Sub-components: `StringFilter`, `SelectFilter`, `NumberFilter` |
| `Form` | `react-hook-form` `FormProvider` + `Controller` wrapper |
| `RouteFocusModal` | Route-based focus modal for create/edit flows |
| `StackedFocusModal` | Nested focus modal for flows within a focus modal |
| `ActionMenu` | Kebab dropdown for row actions |
| `DeletePrompt` | Confirmation dialog for destructive actions |
| `JsonViewSection` | Raw JSON section using `@uiw/react-json-view` |
| `Thumbnail` | Product image with fallback |
| `Skeleton` | Loading skeleton shapes |
| `AmountCell` | Formatted currency cell for tables |
| `ProductCell` | Image + title cell for tables |

## Path aliases

The `@/*` alias maps to `src/admin/*`. Use it for all intra-admin imports:

```ts
import { DataTable } from "@/components/common/table"
import { useCompanies } from "@/hooks/api/companies"
```

For the alias to resolve at bundle time, the host application's `medusa-config.ts` must register the Vite alias — see the plugin root `README.md` for instructions.
